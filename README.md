# 主动智能 · 让个人虾先你一步（Event-Triggered Action Hub）

把个人助理「龙虾」（Lobster）从「定时轮询」升级为 **事件触发的主动智能**：先选一个事件（例如「会议结束」），再订阅一个任务（例如「整理会议纪要」）—— 事件一发生，个人虾就立即按订阅执行你的指令。

本 Demo 用 **两个入口** 演示完整闭环：普通用户用一个页面 **订阅事件任务**，开发管理后台（开发者 + 管理员合一）**提交预置任务并审核上架**。

> ⚠️ 这是纯前端交互演示，**没有真实消息队列 / Webhook / 推送**，也没有登录鉴权（顶部导航切换角色）。
> 部署到 GitHub Pages 的分享版**完全在浏览器内运行**：当前先内置 **2 个事件**（会议开始前 30 分钟、会议结束）+ **3 个预置任务**（生成开场要点、整理会议纪要、归档行动项）。所有交互状态存于 localStorage，刷新不丢，但只存在当前浏览器、不跨设备共享。

## 角色与页面

| 入口 | 页面 / 后台 | 能做什么 |
| --- | --- | --- |
| 🦞 普通用户 | 我的任务 | **我的任务** 开关列表（含 启用 / 草稿 / 待审核 / 已驳回）；**事件市场** 浏览 2 个事件与 3 个预置任务，一键订阅。**2 步向导** 自建：选事件 → 选预置或自定义动作。点开订阅看历次「主动触发执行」记录 |
| 🛠️ 开发管理 | 开发管理后台 | 一个后台用顶部 Tab 切两种身份：**预置任务提案**（开发者「张开发」为现有事件提交新的预置任务）+ **审核**（管理员统一审核「预置任务提案」与「用户自建订阅」，1 步通过 / 驳回，驳回填理由） |

### 2 个事件（v3 模型：先选事件，再订阅任务）
- 🕒 **会议开始前 30 分钟** — 来源飞书日历，每个会议开始前 30 分钟触发；典型任务：生成我的开场要点
- 🏁 **会议结束** — 来源飞书日历，会议结束时触发；典型任务：整理会议纪要、归档行动项

### 创建流程（2 步）
1. **选择事件**：2 个事件卡片，挑一个
2. **选择任务**：用 `Segmented` 切换
   - **从预置任务选** —— 当前事件下已上架的任务，单选即订阅启用
   - **自己写一个** —— 填任务名 + 一段「龙虾会主动做的事」，提交后进入审核队列，管理员通过才可用

> v2 旧模型（6 触发器 + 6 模板市场）已下线。所有旧数据保留在 localStorage 但新版本不再读取；点顶部「重置演示」即恢复到 v3 初始数据。

### 详情页执行历史
每条订阅点开一个抽屉：顶部订阅名 + 事件 + 主动动作摘要，下面是历次执行记录（时间戳 / 成功标识 / token 消耗 / 一段摘要），点右上角 ⚡ 可模拟再触发一次。

### 预置数据（首次打开自动写入浏览器）
- 2 个事件（会议开始前 30 分钟、会议结束）
- 3 个已上架预置任务（生成我的开场要点 / 整理会议纪要 / 归档行动项）+ 1 个审核中提案（同步纪要给未参会人 — by 张开发）
- 3 条已订阅（2 条启用 + 1 条草稿）+ 1 条用户自建、待审核（把纪要同步给直属 leader）
- 每条已启用订阅带 3 条历史执行记录

## 技术栈

- 前端：React 18 + Ant Design 5 + react-router-dom 6（Vite 构建）
- 分享版（GitHub Pages）：**纯静态**，数据由 `packages/shared/store.js` 在浏览器内模拟后端（localStorage 持久化），无需任何服务器
- 本地全栈版（可选）：Python FastAPI 单服务 + SQLite（见文末「本地全栈开发」）
- 零额外渲染依赖：Markdown 与 JSON 高亮均为自研轻量组件，避免离线构建失败

## 目录结构

采用 **npm workspaces monorepo**：共享内核抽出为 `packages/shared`，两个入口各是独立子应用，入口是一个角色选择门户。

```
event-market/
├── package.json                  # npm workspaces：packages/shared + apps/{user,manage}
├── .github/workflows/deploy.yml  # 推送到 main 即自动构建两个子应用并部署到 GitHub Pages
├── packages/shared/              # 共享内核（两个子应用复用）
│   ├── store.js                  # 浏览器内「后端」：数据 + 逻辑 + localStorage
│   ├── api.js                    # 请求封装（分享版指向 store）
│   ├── brand.js                  # 品牌名（改一处全局换名）
│   ├── theme.css
│   └── components/TriggerIcon.jsx
├── apps/                         # 两个独立子应用，各自一套 Vite 工程
│   ├── user/                     # 我的任务（MarketPage）    -> /user/
│   └── manage/                   # 开发管理后台（DeveloperPage + ReviewPage 合为顶部 Tab） -> /manage/
├── public/index.html             # 入口门户：两张卡片（普通用户 / 开发管理）
├── scripts/copy-portal.mjs       # 把入口门户拷贝到构建产物 dist 根
├── backend/                       # 可选：本地全栈版后端（FastAPI + SQLite）
│   ├── app/{main,models,db,seed}.py
│   └── requirements.txt
└── data/event_market.db          # 仅本地全栈版使用
```

> 共享内核经 Vite alias `@shared` 引入（如 `import { api } from '@shared/api.js'`）。每个子应用 `base: './'`、`outDir` 指向 `dist/<角色>`，构建产物与门户一起由 `dist/` 上传。

## 部署到 GitHub Pages（给别人点开就能看）

部署后别人打开链接即可使用，无需安装任何环境。

### 方式一：一键 Fork + Actions 自动部署（推荐）

1. 把这个目录推到你自己的 GitHub 仓库（仓库默认分支需为 `main`）：
   ```bash
   cd event-market
   git init
   git add .
   git commit -m "init 主动智能 demo"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
2. 推送后，GitHub Actions 会自动执行 `.github/workflows/deploy.yml`（构建前端 → 部署到 `gh-pages`）。
3. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
4. 稍等片刻，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可。

> 之后每次 `git push` 到 `main`，站点都会自动更新。

### 方式二：本地直接预览静态产物

不想建仓库也能看效果——在仓库根目录构建两个子应用，用任意静态服务器打开 `dist`：

```bash
cd event-market
npm install            # 安装 workspaces 依赖（含两个子应用）
npm run build          # 构建 user / manage + 拷贝入口门户到 dist/
# 用 Python 起一个静态服务器（或任意静态托管工具）
python -m http.server 4173 --directory dist
# 浏览器打开 http://127.0.0.1:4173  （门户在根，子应用分别在 /user /manage）
```

> 注意：各子应用用 `HashRouter`，链接形如 `…/#/...`，**直接刷新 / 分享深链接都不会 404**；`base: './'` 让资产用相对路径，本地与 Pages 子路径都能正确加载。

## 本地全栈开发（可选，保留真实后端）

若想体验真实的 FastAPI + SQLite 后端（数据跨会话持久化）：

```bash
cd event-market
pip install -r backend/requirements.txt
uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload
# 浏览器打开 http://127.0.0.1:8000
```

前后端分离热更新：再开一个终端 `cd apps/user && npm install && npm run dev`（调试开发管理后台则 `cd apps/manage`），Vite 会把 `/api` 代理到 8000。

## 演示脚本（建议点击顺序）

> 目标：3 分钟走完「订阅事件 → 提交预置任务 → 审核上架」闭环，展示主动智能的价值。

### 0. 开场（我的任务）
1. 打开入口门户，点 **我是普通用户** 进入 **我的任务**（子路径 `/user/`）。页面顶部有「门户首页」「重置演示」。
2. 列表里每条订阅是一个开关：启用后龙虾会按「事件 × 任务」主动执行；待审核的订阅开关为灰、需管理员通过后才能启用；草稿状态可点开关启用。
3. 点开任意一条订阅看执行历史（时间戳 / 成功 / token 消耗 / 摘要），右上角 ⚡ 可模拟再触发一次。
4. 切到 **事件市场** Tab：按事件分 2 组（会议开始前 30 分钟 / 会议结束），每组下展示已上架的预置任务卡；点 **一键订阅** 即可启用。

### 1. 用户自建订阅
5. 点 **新建事件订阅任务**，进入 2 步向导：**选事件** → **选任务**（用 Segmented 切「预置 / 自定义」，自定义时再填 任务名 + 一段「龙虾主动做的事」）。
6. 选「自定义」时填完点 **提交审核**：新建订阅默认进入「待审核」，统计卡「待审核」+1；开关为灰、不能启用，直到管理员通过。

### 2. 开发者提交预置任务（打通供给端）
7. 从门户进入 **开发管理**（子路径 `/manage/`），切到顶部 **预置任务提案** Tab。表格列出「张开发」提交的预置任务，状态有「已上架 / 审核中 / 已驳回」。
8. 点 **提交新预置任务**：选已有事件 → 填名称 / 简介 / 动作预览 → 提交审核。

### 3. 管理员审核（任务审核，闭环收口）
9. 切到顶部 **任务审核** Tab。待审核队列同时含「预置任务提案」与「用户自建订阅」，各自带标签，顶部统计分「预置任务待审 / 自建订阅待审」。
10. 点开一张 **预置任务提案**：看「事件 + 龙虾会主动做的事」；点 **通过** → 上架事件市场；从队列消失；点 **驳回**（必填理由）则不通过并写入审核记录。
11. 点开 **用户自建订阅**：通过即开启该订阅，驳回写理由反馈给用户。
12. （可选）回到 **我的任务**（`/user/`）从「事件市场」一键添加已上架的预置任务，立即出现为一条订阅并启用。

### 4. 复位
- 顶部右侧 **重置演示** 一键恢复为初始数据（仅当前浏览器），方便反复演示。

## 备注

- 分享版所有状态（订阅 / 提交 / 审核）存于浏览器 localStorage，换设备 / 无痕模式不共享，符合 Demo 预期。
- 无鉴权：角色靠前端导航切换，所有操作使用固定演示用户 `demo_user` / 开发者 `张开发`。
- 想换品牌名：改 `packages/shared/brand.js` 一处即可（主名、标题、副标题、slogan 一次搞定）。
